**Equipe:** Paulo Everton Souza Rodrigues · Luan Victor Gurgel Quintela
**Trilha:** Tema 02, Turismo e hotelaria
**Preenchido em:** 17/10/2026 · revisado a cada encontro

| | |
|:---|:---|
| **1 · Contexto de negócio** <br> Uma organização que administra um resort e um hotel urbano. Recebe e administra reservas de hospedagem de diferentes tipos de clientes e canais de venda. A diretoria/gestão decide as políticas de overbooking, canais de venda e estratégias de antecedência de reserva: o objetivo é usar os grupos encontrados para tomar decisões diferentes por perfil. | **2 · A dor** <br> Hoje as reservas são analisadas de forma muito geral, sem saber claramente quais perfis diferentes de reserva existem. Isso dificulta decisões como: quanto aceitar de overbooking, quais canais priorizar, como lidar com reservas de muita ou pouca antecedência, e quais perfis precisam de tratamento diferente. Quem sofre é a gestão do hotel, e, por consequência, a operação inteira. |
| **3 · Objetivo de negócio** <br> Identificar diferentes perfis de reservas e usar essa informação para criar estratégias diferentes por perfil, principalmente em overbooking, canal de venda e antecedência. A ideia não é só "criar clusters", é descobrir como os tipos de reserva se comportam e como o hotel pode agir de forma diferente em cada caso. | **4 · Critério de sucesso do negócio** <br> A diretoria deve conseguir identificar claramente os grupos e usar essa informação para decisões diferenciadas. **Métrica:** percentual de grupos com uma ação de negócio definida. **Meta proposta pela equipe:** 100% dos grupos encontrados devem ter uma característica clara e uma ação definida, já que o próprio enunciado do tema exige que cada grupo receba uma ação diferenciada. |
| **5 · Meta de mineração** <br> Agrupamento (clusterização) das reservas. O objetivo técnico é encontrar grupos de reservas com características semelhantes e entender o que diferencia cada grupo. O tema foi desenhado para técnicas de agrupamento: K-Means, K-Medoids, DBSCAN, hierárquico, entre outras. | **6 · Critério de sucesso técnico** <br> Proposta da equipe (o enunciado do Tema 02 não fixa silhueta mínima nem percentual de ruído): no máximo 5 grupos; silhueta positiva e suficientemente alta para indicar separação razoável; percentual de ruído baixo, se DBSCAN for usado; grupos interpretáveis, ou seja, deve dar para explicar o que diferencia cada um. O limite de 5 grupos vem direto do enunciado: a empresa só financia uma ação diferenciada por grupo, até cinco. |
| **7 · Entidade de análise** <br> Uma reserva de hotel. Cada linha da base representa uma reserva: o próprio enunciado do tema identifica a entidade de análise como "reservas". | **8 · Fonte e volume dos dados** <br> *Hotel Booking Demand* (Antonio, de Almeida & Nunes, 2019), via Kaggle (usuária jessemostipak), artigo original publicado em *Data in Brief*. 119.390 reservas × 32 colunas, dois hotéis diferentes na mesma base. Licença CC BY 4.0. A equipe precisa decidir se os dois hotéis são analisados juntos ou separados: isso está em aberto no enunciado. |
| **9 · Perguntas orientadas a dados** <br> 1. Quais perfis de reserva podem ser identificados considerando antecedência, duração da estadia, canal de venda e comportamento de cancelamento? <br> 2. Quantos grupos de reservas podem ser identificados, respeitando o limite máximo de 5? <br> 3. Quais características diferenciam cada grupo encontrado? <br> 4. Quais grupos apresentam comportamentos diferentes em relação a cancelamento? <br> 5. Como os grupos se distribuem entre resort e hotel urbano, e entre os diferentes canais de venda? | **10 · Restrições e riscos** <br> **Orçamento:** no máximo 5 grupos, porque cada grupo exige uma ação diferente. **Prazo:** 60 dias para apresentar o resultado ao conselho. **Qualidade dos dados:** dois hotéis na mesma base, é preciso decidir tratar junto ou separado. **Dados categóricos:** predominância de informação categórica, exige cuidado na preparação e na escolha de distância. **Vazamento:** `is_canceled` é rótulo, reservado para avaliação, nunca usado para formar os grupos. **Interpretação:** grupo matematicamente diferente não é automaticamente útil para o hotel; cada grupo precisa de leitura de negócio. |
| **11 · Ação esperada por grupo** <br> Para cada grupo, a equipe identifica como o hotel deve tratá-lo de forma diferente: <br>• Reservas com muita antecedência: estratégia específica de confirmação/preço. <br>• Reservas de última hora: política e disponibilidade diferenciadas. <br>• Grupo com maior cancelamento: política de confirmação/cobrança revista. <br>• Grupo concentrado em um canal: estratégia própria para esse canal. <br>• Grupo com padrão de estadia específico: ajuste de venda e operação. <br> O enunciado pede exatamente isso: qual ação cada grupo recebe, e como medir se funcionou. | |

## Em uma frase

> Vamos analisar as reservas de dois tipos de hotel para descobrir quais perfis de reserva existem, entender o comportamento de cada perfil e, a partir disso, definir estratégias diferentes de venda, antecedência e overbooking para cada grupo.
